# Middleware для проверки и повторного получения данных

Нужно реализовать три generic middleware:

- `WithValidate` проверяет результат функции набором валидаторов и защищает программу от паник внутри них;
- `WithRetry` анализирует полученную ошибку и при необходимости повторяет вызов;
- `WithLogs` записывает начало и завершение вызова функции.

Сами данные уже приходят в готовом виде. Работать с сетью, файлами или JSON не требуется.

## Пример использования

```go
request := func() (ExchangeRate, error) {
	return ExchangeRate{
		Currency:         "EUR",
		ChangeMultiplier: 1.02,
		ChangedAt:        time.Now(),
	}, nil
}

validatedRequest := WithValidate(
	request,
	NewFreshnessValidator(30*time.Second),
	NewFieldsValidator(map[string]struct{}{
		"EUR": {},
		"USD": {},
	}),
)

requestWithRetry := WithRetry(validatedRequest, 2)

requestWithLogs := WithLogs(requestWithRetry, logger)

rate, err := requestWithLogs()
```

Middleware независимы и могут использоваться отдельно или в разном порядке.

```go
WithRetry(WithValidate(request, validators...), 2)
```

В таком варианте повторяться могут как временные ошибки самой функции `request`, так и допускающие повтор ошибки валидаторов.

```go
WithValidate(WithRetry(request, 2), validators...)
```

В этом варианте `WithRetry` обрабатывает только ошибки `request`, а валидация выполняется один раз после её успешного завершения. Выбор порядка зависит от требуемого поведения.

## Общие типы

```go
type FetchFunc[T any] func() (T, error)

type Validator[T any] interface {
	Validate(T) error
}

type Logger interface {
	Printf(format string, args ...any)
}
```

Сигнатуры менять нельзя. Middleware должны работать не только с `ExchangeRate`, но и с произвольным типом данных.

## WithValidate

```go
func WithValidate[T any](
	next FetchFunc[T],
	validators ...Validator[T],
) FetchFunc[T]
```

Возвращённая функция должна:

1. Вызвать `next`.
2. Если `next` вернула ошибку, сразу вернуть её и не запускать валидаторы.
3. Последовательно вызвать валидаторы в переданном порядке.
4. После первой ошибки прекратить проверку.
5. Обернуть ошибку валидатора через `%w`, указав его индекс.
6. При любой ошибке вернуть нулевое значение типа `T`.
7. Если все проверки пройдены, вернуть исходные данные.

### Паника валидатора

Реализация `Validator` может вызвать `panic`. Например, в тестах может использоваться такой валидатор:

```go
type PanicValidator struct{}

func (PanicValidator) Validate(ExchangeRate) error {
	panic("validator is broken")
}
```

Паника не должна выходить из `WithValidate` и завершать программу. Её нужно перехватить через `defer` и `recover`, преобразовать в обычную ошибку и сохранить:

- `ErrValidatorPanic` в цепочке ошибок для проверки через `errors.Is`;
- индекс валидатора;
- значение, переданное в `panic`, в тексте ошибки.

После паники следующие валидаторы не запускаются.

## WithRetry

```go
func WithRetry[T any](next FetchFunc[T], retries int) FetchFunc[T]
```

`retries` задаёт количество дополнительных попыток. При `retries == 2` функция `next` может быть вызвана не более трёх раз. Гарантируется, что значение неотрицательно.

После ошибки `WithRetry` должно определить, имеет ли смысл повторять вызов. Анализировать текст `Error()` запрещено.

Правила:

1. Если в цепочке есть `ErrValidatorPanic`, повтор запрещён.
2. Если в цепочке есть `StaleDataError` и данные просрочены меньше чем на 5 минут, повтор разрешён.
3. Если данные просрочены на 5 минут или больше, повтор запрещён.
4. Если в цепочке есть `ErrTemporaryFailure`, повтор разрешён.
5. Все остальные ошибки считаются постоянными и возвращаются без повтора.

При успехе функция сразу возвращает результат. После исчерпания попыток возвращается последняя ошибка. При любой ошибке возвращается нулевое значение типа `T`.

Для анализа обёрнутых ошибок необходимо использовать `errors.Is` и `errors.As`.

## WithLogs

```go
func WithLogs[T any](next FetchFunc[T], logger Logger) FetchFunc[T]
```

Возвращённая функция должна:

1. Непосредственно перед вызовом `next` записать сообщение о начале работы и текущее время.
2. После завершения `next` записать сообщение о завершении и новое текущее время.
3. Вернуть результат и ошибку `next` без изменений.

Для времени используется формат `time.RFC3339Nano`. Формат сообщений:

```text
функция начата в <время>
функция завершена в <время>
```

Запись о завершении должна выполняться через `defer`, чтобы она появилась и в случае паники внутри `next`. Саму панику `WithLogs` перехватывать не должно.

## Модель курса валюты

```go
type ExchangeRate struct {
	Currency         string
	ChangeMultiplier float64
	ChangedAt        time.Time
}
```

`ChangeMultiplier` показывает, во сколько раз изменился курс. Например, `1.02` означает рост на 2%, а `0.97` — снижение на 3%.

## Валидатор актуальности

Валидатор создаётся конструктором:

```go
func NewFreshnessValidator(maxAge time.Duration) Validator[ExchangeRate]
```

`maxAge` задаёт период, в течение которого данные не считаются устаревшими относительно текущего времени.

Валидатор проверяет только инвариант актуальности:

- возраст не больше `maxAge` — вернуть `nil`;
- возраст больше `maxAge` — вернуть `*StaleDataError`.

Валидатор актуальности не решает, можно ли повторять запрос. Это решение принимает `WithRetry`.

`StaleDataError` должна хранить отклонённый `ExchangeRate` и `StaleFor` — время, на которое фактический возраст превысил `maxAge`. Валидатор только сообщает эти факты и ничего не знает о retry-политике.

`WithRetry` извлекает `StaleDataError` через `errors.As`, анализирует её данные и самостоятельно принимает решение о повторе. Метод `Error()` должен вернуть понятное описание нарушения.

## Валидатор полей

Валидатор создаётся конструктором, принимающим множество поддерживаемых валют:

```go
func NewFieldsValidator(
	supportedCurrencies map[string]struct{},
) Validator[ExchangeRate]
```

Валидатор проверяет инварианты содержимого:

- `Currency` не должна быть пустой;
- `Currency` должна присутствовать в переданном множестве поддерживаемых валют;
- `ChangeMultiplier` должен быть больше нуля.

При нарушении правила возвращается обычная ошибка с понятным сообщением. Конкретный способ её создания условием не задаётся.

Ошибки валидатора полей не допускают повторную попытку.

## Ограничения

- Нельзя изменять сигнатуры предоставленных функций и интерфейсов.
- Нельзя принимать решения по тексту ошибки.
- Нельзя использовать сторонние библиотеки.
- Все заранее объявленные sentinel-ошибки должны находиться в `middlewares.go`.
